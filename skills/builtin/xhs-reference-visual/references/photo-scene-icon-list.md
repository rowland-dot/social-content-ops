# 图标清单（issue 86）

照片场景帖的套系计划里的图标清单，细则都在这里；SKILL.md 只留门、出图规则和检查，各自指回这里。

负责人的规则（CLAUDE.md“Photo-scene post images follow one approval process”第 2 步）：。

## 什么算图标

- 图标是 Easel 自己加到照片上、用来表示一件事的小符号：对勾、箭头、时钟、水滴、爱心、星、编号徽章的形状。
- 文字和数字是字，不是图标，归字体体系。
- 装饰字的涂鸦（例如标题旁的小装饰）归负责人选的字体样式，不在清单里；单独出现、表示一个意思的符号才是图标。
- 真实包装上印的符号不在清单里，也从不读、不列、不核对包装上印的字（见 SKILL.md 里负责人的规则）。场景自带的东西也不是图标。

## 清单怎么写

- 整套唯一一张图标清单，写进 `set-plan.md`，在画任何一张之前写完。每个图标一行：
  - 图标：用平常话描述它画的是什么（例如“细线对勾”），再写怎么画：线条还是填充，线宽；
  - 它的唯一意思；
  - 出现在哪几张卡。
- 一个图标一个意思，一个意思一个图标：一个对勾不能同时表示“做完了”和“推荐”，也不能有两个不同的图标都表示“做完了”。两个不同的图标表示同一个意思，清单不成立。
- 清单可以是空的。这套不用图标，就在计划里写“这套不用图标”；写了以后，卡上出现任何图标都不合格。技能不替这套做默认：清单取自这篇帖子自己的主题研究存下的图集和团队设计记忆，写明这张清单取自哪几套（文件名）。
- 没有清单也没有这句话的套系计划没有写完，不交给用户，也不画任何一张卡。

## 和颜色表的关系

清单里的图标如果本身就是颜色和层级的对应表里的一个层级（例如对勾），它穿那一层的颜色；两张表要对得上，不能一张写一个色、另一张写另一个色。

## 交给用户

清单随套系计划一起交给用户，放在计划页上，不跟着小样走。每个图标有描述和意思，计划页（issue 87）靠它画出图标；用户批准的是计划、颜色和图标一次过。

## 出图和检查

- 提示词：每张卡的提示词逐个写出这张卡上清单里的图标，带描述、意思和位置（位置取自这张卡的版面计划），不画清单以外的任何符号。打字字体的整套也一样：设字只设字，图标仍然由 Codex 画。
- 检查：画完以后，每张卡对着清单看一遍，整套并排时再看一遍。画了清单以外的图标、清单里的图标用在了它的意思以外、整套里两个不同的图标表示同一个意思，这张卡不合格。检查用眼睛，不读包装上印的字。

## 资料包里的两句话原样不动

团队标准 STANDARD.md 里的“图标风格、线宽、间距统一”只要求样式一致，不管意思；设计记忆 DESIGN-MEMORY.md 里的“箭头和图标可能暗示效果，不能只审核文字而忽视其视觉含义。”正是为什么每个图标要有写下来的意思。这里是在细化它们：资料包里的这两句原样不动，不改、不补。
