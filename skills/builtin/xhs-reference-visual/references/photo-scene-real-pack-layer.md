# 真实包装图层：Codex 改了包装，失败的重出到 2 次还不行，就把真实商品照放进去（issue 108）

Codex 会改包装。先重出；失败的重出到 2 次、问题还在，这张卡改用真实包装图层：Codex 只画场景，包装由代码把真实商品照放进去。判断全凭眼睛，看形状和颜色，不读、不列、不报包装上印的字。



资料包只把“保留原产品像素的抠图/合成”写成候选办法，并写着“采用前需确认可用工具及授权”（`<资料包目录>/` 里的评审和记忆文件，原样不动）。负责人的这条规则就是这个授权。

## 次数

- 每张卡各记各的：重出之后真实包装的眼睛检查（形状、比例、颜色、Logo 和标签的位置、有没有多出或少掉）仍不合格，记一次失败的重出。
- 第一次画不算重出。其他原因不合格的不计入（AI 感、字、道具、手、版面）。所以一张卡的包装由 Codex 画三次后就换图层：第一次画，加 2 次重出。
- 次数写进每一版保存的提示词文件。干净重出和已批准卡的修改两条路都算，同一个次数。

## 切换

失败的重出到 2 次、包装仍不合格时，下一次画这张卡改用真实包装图层，不再让 Codex 重画包装。其他原因的重出仍照干净重出（issue 78），没有次数上限。

## 手托着包装的卡

计划里手托着、打开或倒出包装的卡，包装放不进手里，不走图层。这样的卡次数到 2 时，在再画之前停下，用问题工具问用户，选项只有三个：

- 这张卡改成包装放在手旁边的台面上（推荐）
- 这张卡不放包装
- 再让 Codex 重画一次

## 场景层

- Codex 照这张卡的参考图重新画场景（有人的卡再传身份图），照干净重出办：不用这张卡任何旧版本当输入。
- 提示词写明不画包装和商品，并在这张卡版面计划里包装的位置留一块干净平整的表面，光照这张卡计划的光。
- 商品照不以商品图的角色传入（那个角色是让 Codex 画包装）。参考图用 `--style-image` 传，没有商品图：`python skills/shared/scripts/ai_image.py img2img --prompt "…" --style-image <参考图> [--identity-image <模特图>] --size 3:4 --output …`。

## 包装层

1. 从这张卡点名的那张真实商品照（issue 107）用本地免费的 `remove_bg.py remove`（remove-bg 技能）抠出包装，得到带透明通道的 PNG。不需要 Codex。
2. 用 `python3 skills/shared/scripts/image_ops.py place --scene <场景层> --layer <抠出的包装> --x <中心横向比例> --y <中心纵向比例> --width <宽占场景宽的比例> --shadow-dx … --shadow-dy … --record <记录.json> -o <成图>`，位置和大小取自这张卡的版面计划。
3. 包装只等比缩放和平移，不改色、不变形、不转向、不重画。接触阴影由代码按抠图的轮廓画：在包装下面和后面，落在背离光的一侧（光从左来，`--shadow-dx` 为正）。

## 图层顺序

先场景，再包装图层，最后（打字字体的整套）打字字。手绘的字和涂鸦留在 Codex 画的场景里。

## 记录

每张用了图层的卡保留：场景层（贴包装和打字字之前），和一份记录：用了哪张照片、位置、缩放、阴影设置（`place --record` 写出）。负责人要改一张已批准的图层卡时（issue 91），改的是它的场景层，包装用同一份记录再放一次。

## 交付前检查：真实包装图层检查（issue 108，【一级】）

用图层的卡，把图和它的计划并排，只看形状和光：

- 包装放在表面上，不是悬空；
- 影子落在背离场景光的一侧；
- 包装的大小合适这个场景；
- 抠出的边缘干净，没有白边或残留的背景；
- Codex 没有多画第二个或半个包装。

任何一条不合格：先在代码里修（位置、大小、阴影），或把场景层干净重出，或如实报告，不能当合格交付。这一级和别的一级检查一样，不读、不列、不报包装上印的字。

## 交付说明

用了图层的卡，交付时写明：这张卡的包装是代码放进去的真实商品照片。
