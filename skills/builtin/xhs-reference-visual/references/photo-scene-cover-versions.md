# 四个封面版本 A/B/C/D（issue 88、140）

照片场景帖不再先出一张小样。计划页批准之后，画四个封面 A、B、C、D，并排给用户（默认田字格），用户选一个，其余的卡跟着选定的方向画。细则都在这里；SKILL.md 只留步骤和负责人的规则，各自指回这里。

负责人的规则（CLAUDE.md“Photo-scene post images follow one approval process”第 4 步）：。

## 四个方向写进套系计划

- 套系计划里有一张封面方向表，列和每一格怎么写，固定在 [photo-scene-plan-page.md](photo-scene-plan-page.md) 的“封面方向”一节；表和套系计划里其他的表一起上计划页，用户一次批准。
- 每个方向各有一份版面计划（写法同“版面计划”那一节：这个封面上的每一块字讲什么、归哪一组、放在哪里和为什么、阅读顺序），也写在套系计划旁边，画任何一张之前写完；它不上计划页，画封面时才用。
- 四个方向借四套不同的图集：取自这篇帖子自己的主题研究存下的图集，团队的参考图不算一套。“研究的图集”不足四套时，如实告诉用户这篇帖子的研究不够四套，然后停下；不重用一套，也不凭空编方向。
- 只算真正的不同：四个方向借四套不同的图集，两两比较，角度、取景和领头每一样都不同；换个颜色或裁小一点不是不同的方向。画之前先在文字里筛至少五个候选、留下四个，见 [photo-scene-cover-screening.md](photo-scene-cover-screening.md)（issue 99）。
- 一个方向如果会占用后面某一张卡已经计划好的画面（例如封面用了第 4 张的画面，或封面做成宫格就占了第 3 张的宫格），在“撞上的卡和改法”那一格写明那张卡，和选哪个方向，那张卡就怎么改。计划页上用户批准的就包括这个改法，选定之后照改，不再另问。

## 画四个封面

- 计划页的批准就是放行：用户批准计划页之后直接画，不再问第二次。这条路线不花钱，但耗负责人的 ChatGPT 额度，四个封面各一次是计划页批准时已经看到的数目。
- 一次一张，按 A、B、C、D 的顺序，每张用 SKILL.md“出图”里已有的命令，传入商品照和这个方向借的那一套的参考；每一张都过“交付前检查实际图片”里已有的各项：AI 感检查、手和动作检查、真实包装只用眼睛看、Easel 自己加的字逐字核对。打字字体的整套，字由代码按样式设上（issue 81），四个封面带的字都是计划里写的那一句；手绘的封面自带它的字，所以选定封面上的字总是原版加三个新的里的那个原版。
- 哪一个封面不合格，只重画那一个，按“干净重出”从原始商品照和参考图重画；不拿别的方向的封面当底图。
- 四个封面都画好、都合格之前，不交给用户；有一个交不出，如实报告，不拿三张凑数。

## 并排给用户看

命令从套系计划建封面对比页：

```
python3 skills/builtin/xhs-reference-visual/scripts/plan_page.py covers --plan <set-plan.md> [--images-folder <封面所在的文件夹>] [--row] [-o <页的路径>]
```

- 封面图放在帖子的 `images/` 里（`set-plan.md` 旁边），文件名是 `cover-A`、`cover-B`、`cover-C`、`cover-D`（png、jpg、jpeg 或 webp 都行，每个方向只能有一张）；封面在别处时传 `--images-folder`。
- 页由命令建，从不手写：四个封面并排，各自标着 A、B、C、D，每个封面下面是它在封面方向表里的那一行，每一格逐字复制，不改写、不缩写；图片用相对路径，整个文件夹挪走页也打得开。页存成 `封面对比页.html`，在 `set-plan.md` 旁边，存在 `outputs/` 里这篇帖子的照片场景目录。
- 排法：默认是田字格（两行两列），团队在手机上看得清；负责人说要在电脑上看时加 `--row`，同样四个封面排成一行，从左到右。容器的类名是 `covers grid` 或 `covers row`。
- 退出码 0：页建好了，命令打印页的路径。退出码 2：输入不对（封面方向表读不通，或某个方向少了封面图，或有两张），什么也不写；先改，再建。
- 把页的位置交给用户，然后停下。用户选定之前，其他任何一张卡都不画。

## 用户选定之后

- 选定的封面就是这套的封面，不再重画；它算负责人已经批准的卡（SKILL.md“已批准卡的修改”里的“他选中的封面”）。选定的是哪一个、哪一天，记入批准记录 `approvals.json`（`kind` 是 `cover-pick`，见 [photo-scene-approvals.md](photo-scene-approvals.md)），不写进 `set-plan.md`；同时原样记下选定方向的记忆点，仍记在 `set-plan.md` 里，作为这套封面的记忆点（后面的卡没有记忆点；见 [photo-scene-memory-point.md](photo-scene-memory-point.md)）。
- 记下选定之后，先在这张封面上再选字体和样式，各是原版加三个新的，四选一 A 到 D（[photo-scene-lettering-picks.md](photo-scene-lettering-picks.md)），选完才画其余的卡。
- 选定的方向如果撞上后面某一张卡，把套系计划里那张卡的一行按方向表写的改法改掉；其余的卡跟着选定的方向，用选定的封面当字体和风格参考，一张一张画。
- 没选的三张留在磁盘上，在文件名或套系计划里标明没选；不删，也不再用。
- 用户的选择只能来自他自己的回复；沉默、没有反对、猜他会选哪个都不算，也不替他选。

## 不在这里

- 比四个更多的候选方向、各方向共用的三个轴、两个方向混着选（“A 加 C”，用 `covers --mix A+C` 建只有这张混合封面的页）：issue 99，见 [photo-scene-cover-screening.md](photo-scene-cover-screening.md)。
- 封面的字体和样式的 A/B/C/D 选择：issue 89，选定封面之后、其余的卡画之前做，写在 [photo-scene-lettering-picks.md](photo-scene-lettering-picks.md)。
- 其余的卡一口气画完再并排给用户看：issue 90。
- 不读、不列、不报包装上印的字（见 SKILL.md 里负责人的规则）；封面方向、对比页和检查都只看场景和真实包装的样子。
- 团队资料包里“先做小样”和“同风格微变体”的句子，SKILL.md 里写明负责人的规则压过它们；资料包里的文件不改。
