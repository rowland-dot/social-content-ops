# 交付前检查的顺序（issue 100）

先结构后表面。每张卡的检查分三级，从上往下做：

| 级 | 管什么 | 放在这一级的检查 |
|---|---|---|
| 一级 产品和版面 | 对的商品、对的人、这张卡计划的版面 | 真实包装只用眼睛看；深色包装分离检查（深色包装融进背景，issue 106）；包装的面检查（画出照片里没有的面，issue 107）；真实包装图层检查（用了图层的卡：悬空、影子方向、大小、边缘、多画的包装，issue 108）；状态检查（显示状态的卡：商品除了闭合包装之外的任何状态和点名的来源颜色、质地、清澈度明显不同，issue 109）；人物和身份检查；删掉商品测试；字不按版面计划放（漏字、归组不对、位置不对）；包装在不止一张卡上是主角；泄漏检查里图的泄漏（学过的帖子的品牌、商品、人物、徽章、整个版面）；照片没有画出这张卡的字说到的东西（issue 122）；正文没有对齐或间距不均（issue 126）；标题比封面标题小；标题落在白底条上；脸和已批准封面的脸不同（issue 127） |
| 二级 构图 | 画面怎么搭 | 两张卡构图重复；手和动作检查；人物和画面真实感检查；道具（不证明这张卡的小动作、计划外、杂乱、只为填满画面、没要求的镜子）；卡上的地方不是这套的地方；特写没有写明用途；安全边距检查里的主体被切掉或落在边距里；AI 感检查里“眼睛没有第一个落点”；整套并排时某张卡的光不是封面的光（issue 122） |
| 三级 字和颜色 | 表面 | 逐字核对 Easel 自己加的字；打字字体一致检查；手绘的字或涂鸦被切掉或落在边距里（安全边距检查）；某张卡的标题字体和封面、参考图不一致；正文带了标题的样式、正文混用字形、同一正文层级两个字号、卖点行没有高亮（issue 126）；篇名带色块（issue 127）；表情缺了或不是 iOS 样式（easel-setup-gaps issue 100）；手绘字的形态检查（漏了计划写的特征或超过计划写的档位，issue 113）；颜色和层级检查；图标检查；泄漏检查里字的泄漏（学过的帖子的说法、对比页上的字、上一张卡的字）；AI 感检查里的色偏、颜色铺满画面、发雾发光、同一种颗粒感 |

读像素尺寸不算一级，是做检查之前的前提。每个检查或每个不合格的迹象只属于一级。一条检查里有几级的迹象时，SKILL.md 里每个迹象前面写着自己的级别，也按级别的顺序排。

## 规则

- 检查从上往下做：一级、二级、三级。
- 一张卡不合格时，在最高的那一级修：下一次重出的改正过的提示词针对那一级。低级的问题写进这张卡的提示词文件，重出之后再检查。
- 每次重出之后，所有检查从一级重新做，因为一次重出可能改变整张图。
- 一级或二级不合格的卡，只改三级（字、字体、打字字体的样式、颜色）不算合格。
- 打字字体的整套只重设字（不重画底图）这条路，只在一级和二级都合格时才可以。
- 套系并排检查也按这个顺序：一级或二级不合格的整套不交付，字怎么改都不行。
- 没有批准的卡照干净重出办（issue 78），已批准的卡照“已批准卡的修改”办（issue 91）。这一条只决定先修哪一个问题，重出没有次数上限（issue 101 不加上限）。
- 之后新加的检查，要写明自己属于哪一级。

这一页不读、不列、不报包装上印的字（见 SKILL.md 里负责人的规则）。
