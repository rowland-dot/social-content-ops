# 小红书参考视觉（照片场景帖）

团队的整包资料放在私有文件夹里（`work/team-packages/xhs-reference-visual/`），用法以它为准；没有团队资料包时，由用户在技能自带的默认资料包（`references/defaults/`，不含参考图）和自建资料包之间选。本文件只写 Easel 里怎么落实，团队的规则不在这里改写。下面把资料包所在的文件夹叫“资料包目录”，写作 `<资料包目录>`。找资料包（在任何研究、计划和出图之前）：运行 `python3 skills/builtin/xhs-reference-visual/scripts/package.py find`。它打印“资料包目录：…”就用那个文件夹，什么也不问用户。它打印没找到团队资料包的选择（退出码 3）时，用问题工具把 A（默认资料包）和 B（建立自己的资料包）原样问给用户，得到回答后运行 `package.py find --choice default` 或 `package.py find --choice own`；选 B 时它列出需要的文件和位置，等用户放好再从头开始。用户随时想看默认资料包里写了什么，运行 `package.py show-default`，把文件拿给用户看。套系计划开头写一行“资料包目录：路径”。团队资料包和默认资料包里有几个文件位置不同，后面各处写的是团队资料包里的位置，用默认资料包时按 [package-layouts.md](references/package-layouts.md) 的对照表找同名的那一份。

## 只在两种情况下启动

1. 用户点名要这个技能，或说“照片场景帖”“photo-scene post”“小红书参考视觉”。
2. 用户在 [xhs-note-creator](../xhs-note-creator/SKILL.md) 的开场提问里选了“照片场景帖”，由它把出图这一步交过来。

其他情况一律不启动：别的技能、别的出图需求，哪怕看起来合适，也不自己拿来用。文字卡仍走 card-xiaohongshu。

## 动手前先读（按顺序，从头读到尾）

0. 这个账号的创作指南，在任何研究、计划和出图之前：运行 `python3 skills/shared/scripts/creation_guide.py check --brand <品牌>`，把它给出的创作指南整份读完；套系计划在第一个 `##` 段落之前写一行“创作指南：路径（最后修改 日期）”。没有创作指南就停下，告诉负责人并提议从 `profiles/_template/creation-guide.md` 建，其间不画不写。细则见 [photo-scene-creation-guide.md](references/photo-scene-creation-guide.md)。
1. `<资料包目录>/skill/SKILL.md`：团队技能入口，它的相对链接以 `<资料包目录>/` 为根。
2. `<资料包目录>/file/DESIGN-MEMORY.md`，再读当前品牌自己的文件，在品牌的画像目录里（步骤 0 打印出的创作指南所在的文件夹）：`photo-scene/file/<品牌>.md`（<品牌> 是该品牌文件的名字）。品牌的风格文件、参考图和案例索引都不在技能里。画像目录里没有 `photo-scene/`，就是这个品牌没有团队参考图：如实说一句“这个品牌没有团队参考图”，然后继续，也不去别的品牌那里找。
3. `photo-scene/case/CASES.md`（同在画像目录里，只含本品牌的）：选主参考、辅参考；实际打开所选原图看，图在 `photo-scene/case/references/<品牌>/<图>`。
4. `<资料包目录>/playbook/PLAYBOOK.md` 读完整；每张图的执行说明按 `<资料包目录>/playbook/EXECUTION-BRIEF.md`。
5. 设计记忆提到的旧标准：`<资料包目录>/standards/ecommerce-natural-v1/STANDARD.md` 和 `<资料包目录>/standards/ecommerce-natural-v1/CASES.md`，出任何图之前读。

团队资料包的来源和哈希清单在私有文件夹里（`work/docs/vendored/xhs-reference-visual-source.md`），默认资料包没有这两份。`<资料包目录>/` 里的文件不改、不补、不重排；Easel 自己的内容只写在本文件和品牌画像里。

**负责人的规则压过资料包里所有要读包装上印的字的句子（以负责人的规则为准）。** 真实商品包装上印的字，不论中文、英文还是别的语言，从不核对、不列清单、不放大比对、不拿去问用户，也不作为缩小、裁掉或藏起包装的理由。资料包里凡是要求确认、核实、放大或比对包装或标签上的字的句子，一律不执行，例如 `<资料包目录>/playbook/PLAYBOOK.md` 里“所有上图文字须经用户确认，包括……和所谓真实标签”的这一句，以及同类的“核对……容量、标签”“包装文字以用户提供的可核验资料为准”“包装小字”“局部放大图”。这些句子里的其余要求照旧有效。资料包里其余同类的句子（品牌文件、旧标准、提示词技能、置换记忆、置换评审和案例里要锁定、核对、纠正或放大比对包装文字的）逐条点名在 [pack-wording-override.md](references/pack-wording-override.md)，读完它：每条的包装文字部分不执行，其余照旧。要确认真实包装的，只看它是不是真包装，见下面“交付前检查实际图片”。

**负责人的“干净重出”规则（2026-10-27）对负责人没有批准的卡，压过资料包里提示词技能 `<资料包目录>/prompt-skill/my-precise-image-generation-prompt/SKILL.md` 的一句话（以负责人的规则为准）：“发现明确缺陷时进行有针对性的修正，避免反复全图重生成造成漂移”。** 在 Easel 里，一张没有批准的卡不合格，就按下面“出图”里的干净重出办：从原始商品照和参考图重新画，不在上一版上改。在上一版上接着改，会越改越脏（“越改越脏”，Lovart 的清理技能也这么说）。那句话在资料包里原样不动，这里对没有批准的卡只是不执行它。负责人已经批准的卡不在这条之内：负责人 2026-10-28 的规则（issue 91，见下面“出图”里的“已批准卡的修改”）要求从那张已批准的卡改起、只改负责人点名的地方，这和资料包那句话的意思一致，所以对已批准的卡，两者不冲突。

**负责人的“整套一个地方”规则（2026-10-27，issue 79 起叫“整套一个家”；issue 118 起这个地方来自帖子主题）压过资料包里 `<资料包目录>/playbook/PLAYBOOK.md` 的“套系背景差异检查”的一句话（以负责人的规则为准）：“仅换产品左右位置、手势或添加瑜伽垫，不足以形成明显不同背景”。** 那句话要的是每张卡的背景明显不同；负责人选的是整套留在同一个地方，所以在 Easel 里卡与卡的区别来自角落、台面、机位和主体，不来自换一个新地方（见下面“手和动作”一节的“同一个地方”）。那句话在资料包里原样不动，这里只是不执行它。

## 画图之前：先写套系计划和版面计划（issue 73）

负责人的规则（CLAUDE.md“内容从真实帖子里学，从不凭空编”）：先学真实帖子，再动手。团队的整包资料一张一张地写执行说明，没有“整套怎么排”这一步，所以这里补上；这两份计划都写在帖子的产物目录里，画任何一张之前先写完。

**这篇帖子自己的主题研究（issue 82；负责人，2026-10-28，CLAUDE.md“Photo-scene post images follow one approval process”第 1 步）**
- 门：这篇帖子自己的主题研究没有存在之前，`set-plan.md` 不写，版面计划不写，任何一张卡也不画。（一篇帖子的总印象分是点赞加收藏合起来）；
- 研究是什么：针对这篇帖子自己的主题做一次搜索（小红书），把图片帖按点赞加收藏的合计从高到低排，取最高的几篇，把整套图集（不只封面）存进品牌资料/对标笔记库/image-sets 文件夹，并附一份书面小结。
- 计划点名：套系计划开头写明用的是哪一次研究：搜的主题、排名（每套的点赞、收藏和合计）、存下的图集文件名、小结文件名。没有点名的计划不成立，不能写进 `set-plan.md`。
- 拒绝：别的帖子主题下存的图集，不算这篇帖子的研究；团队的参考图单独也不能当研究。两者都不能写进计划当作这次的研究。团队的参考图仍照旧当主参考、辅参考用，但只在这篇帖子自己的研究之外补充。
- 没有这篇帖子自己的研究：如实告诉用户这个主题还没有研究，然后停下。不凭空编套系，也不拿别的主题的图集顶替。怎么搜、怎么排名、怎么存图归 issue 83、84（排名）和 issue 84（存图）：用小红书笔记整篇读取技能里的 `python3 skills/builtin/skill-xhs-note-reader/scripts/study_topic.py --brand <品牌> --keyword <主题>` 做这一步，用法和小结的写法见 [photo-scene-topic-study.md](references/photo-scene-topic-study.md)，没有这条命令存的图集不算研究；这里只管这道门。

**套系计划（`set-plan.md`）**
- 先看这篇帖子自己的主题研究存下的图集（见上面的门）：品牌资料/对标笔记库/image-sets 文件夹里这次研究存的整套图集；团队的参考图（品牌画像目录里 `photo-scene/case/CASES.md` 选出的主参考、辅参考）只补充，不顶替。要看整套图集，不只看封面：后几张怎么排、包装什么时候退场、字怎么写，都要看。
- 没有可研究的：这篇帖子自己的主题研究不存在（上面的门不过）时，如实告诉用户，然后停下。不凭空编套系，团队参考图也不顶替。
- 计划写明这篇帖子的主题研究（见上面）和研究了哪几套（文件名），再逐张写：这张卡的字说到或承诺的东西（issue 122，要画出来的，见 [photo-scene-composition.md](references/photo-scene-composition.md)）、这张卡回答的读者的问题（见下面“读者的问题”）、主体、场景、机位、短文案，以及这一张的包装角色（主角、使用中、很小或只露一角、不出现）。 深色包装（issue 106）：计划里看真实商品照，用眼睛记一次这个包装是不是深色（主体是黑色或很深）；是的话，有它出现的每张卡的计划都写明用哪些光和边的办法让它和背景分开，细则见 [photo-scene-dark-pack.md](references/photo-scene-dark-pack.md)。 封面的光（issue 122）：封面选定后写一次封面的光（方向、软硬、一天里的时间），见 [photo-scene-composition.md](references/photo-scene-composition.md)。 包装的面（issue 107）：计划另列真实包装照片清单，每张有包装的卡点名一张照片和它露出的面，缺的面先问用户，不画猜的，细则见 [photo-scene-pack-faces.md](references/photo-scene-pack-faces.md)。
- 默认走“封面加步骤故事”：只有封面是设计过的；后面每张是一个真实的下一步照片（这个商品的使用顺序里一个接一个的小动作），每张一句短文案，小而朴素的框；同一个地方，每张换一个新主体。只有研究的参考图集显示另一种排法时才换，并在计划里写明依据是哪几套。 真实状态来源（issue 109）：这些步骤里每个显示商品除了闭合包装之外的任何状态的，都要点名一张这个品牌自己商品的真实图，没有就停下来问，细则见 [photo-scene-product-states.md](references/photo-scene-product-states.md)。
- 包装最多在一张卡上是主角（占画面大块的主体）；其他卡可以拍它在使用中、很小或只露一角，也可以不出现。没有包装的卡也是好卡。这条只管包装占多大、出现几次，不涉及包装上的字（见上面负责人的规则）。
- 字体体系：整套的字体和样式不由计划自己定，由负责人在选定的封面上选（见下面“先画三个封面 A/B/C”里选定封面之后的两步选择）；团队设计记忆（`<资料包目录>/file/DESIGN-MEMORY.md` 里的三种，加上它的承托形式：笔刷、白描边、便签等）只是选项的来源。选定后写进这一行：这套的字是哪一种：打字字体（一种真实的已装字体，由代码设字）还是手绘（Codex 画）。手绘的标题字，这个体系写进每一张的提示词（只写在标题的那几块），一张都不能漏；选的字体和样式只给标题，正文用整套一个朴素的正文样式，计划要有“正文样式一行”（字形、墨色、各正文层级字号、参考卡或“还没有”），没有这一行计划没有写完，细则见 [photo-scene-body-text.md](references/photo-scene-body-text.md)；套系计划在这一段还写一个标题字号（封面标题和每张卡的页标题同一个值，标题在照片上，篇名是没有色块的正文小标题），细则见 [photo-scene-title-and-face.md](references/photo-scene-title-and-face.md)（issue 127）；打字字体的字不进提示词，样式存成样式文件，见下面“打字字体的整套”。提示词没有字体说明，或要求系统默认字体、普通无衬线字、Arial 一类的网页默认字体，不进入出图；这类字体写法一律拒绝，例如 "small plain rectangular label boxes"（朴素白方框加深色字，没说字体）这种句子不许出现在提示词里。 手绘的字（issue 113）：Codex 画的每一个字体样式，这一行还要写四部分：设计记忆里的类、至少五项在图上看得见的形态特征、字形压扁程度/笔画松紧度/基线波浪起伏强度三个档位（基线最多轻）、一张参考图加一句借用句；缺任何一部分，计划没有写完，不画任何一张卡，细则见 [photo-scene-lettering-brief.md](references/photo-scene-lettering-brief.md)。

**版面计划（`layout-plan.md`，每张卡一份）**
- 出每一张之前，列出这张卡上的每一块字：它讲什么、归哪一组、放在哪里和为什么（位置和理由）、阅读顺序。
- 同类的字（全部配方要点、全部使用步骤）是一组：同一种样式，对齐排在一起。位置由这块字讲什么决定，不照词表的顺序或位置备注。词表里写的“底部小字”这类备注不决定位置：禁止把它写成 "a tiny line at the bottom" 这样的提示词，一个配方要点孤零零放在底部，而其他配方要点在上面成列。
- 写完提示词，对着这张卡的版面计划查一遍：字有没有漏、归组对不对、位置对不对，不对先改再出图。整块字（描边和阴影都算在内）都要放在安全边距里面，不只是中心点（issue 104，见 [photo-scene-safe-margin.md](references/photo-scene-safe-margin.md)）。 手绘字（issue 113）：提示词带上这个样式的特征、档位和借用句，照计划原样抄，也查在不在。

**读者的问题（issue 80；来源：Lovart 技能包评审（私有文件夹 work/ 里的评审），Lovart 的文件没有拿进来，关于包装印字的那一句也没有拿）**
- 套系计划给每一张卡（封面也算）写一行：读者翻到这一步心里的那个问题，这张卡回答它。画任何一张之前写完。这是在细化团队标准 `<资料包目录>/standards/ecommerce-natural-v1/STANDARD.md` 里“每张图片或每屏有明确任务”那一句：任务具体到读者的一个问题。资料包里的那一句原样不动。封面另有“记忆点”，见 [photo-scene-memory-point.md](references/photo-scene-memory-point.md)。
- 问题用中文，用读者自己的话，写到那个时刻的具体程度，例如读者在这一步真会问的一个具体的数量或条件，不写“怎么用”这样的大类。大类（这是什么、为什么要在意、怎么用、凭什么信、适不适合我、下一步做什么）只是举例，不是固定菜单。封面加步骤故事里的几张步骤卡不会因为都算“怎么用”就被当成重复，因为每张问的是不同的具体问题。
- 两张卡问的是同一个问题，计划要写明两张都要的理由，否则删掉其中一张。套系有几张卡取决于故事要回答几个问题：不预先定张数，也不为凑张数加卡。
- 问题的先后来自已存的真实图集和上面的“封面加步骤故事”。Lovart 评审里推荐帖和教程帖的故事顺序，只有计划写明已存的哪几套真实图集显示了这种顺序，才能用。“内容从真实帖子里学”和“封面加步骤故事”都在它们之上。
- 问题不问包装上印的字写了什么（见上面负责人的规则）。

**场景和道具（issue 77；来源：Lovart 技能包评审（私有文件夹 work/ 里的评审），Lovart 的文件没有拿进来，关于包装印字的那一句也没有拿）**
- 地方从帖子主题来，小事从商品来（issue 118；负责人，2026-10-28，CLAUDE.md“Photo-scene post images follow one approval process”下的这件事：）。套系计划按这篇帖子讲什么，先写这套的地方：健身帖是健身房，日常生活帖是有生活气的房间，工作或通勤帖是工作的地方或通勤路上，旅行或户外帖是旅途或户外。由计划自己推出，从不问用户，也不问负责人。这四类都不是的，地方取自这篇帖子自己研究的图集，写进计划。计划再列出这个地方里本来就有的普通东西，取自这篇帖子自己研究的图集（点名文件名）；它们是场景，不是道具，不占下面的 3 件。写计划前读完 [photo-scene-setting.md](references/photo-scene-setting.md)。参考图仍然给光线、构图和字体风格，不再单独决定场景。

- 随手拿来、不来自商品的道具，例如咖啡杯、书、植物、毯子，放进小动作或前景的，在计划里一律拒绝，也不进提示词；地方里普通的东西不在这条之内。植物只在这个商品的日常真的有它时才算商品的道具。

**手和动作（issue 79；来源：Lovart 技能包评审（私有文件夹 work/ 里的评审），Lovart 的文件没有拿进来，关于包装印字的那一句也没有拿）**
- 有手或手臂入画的卡（拿着商品、打开、取用、手里的物件），套系计划逐张写清下面六样，缺一样的卡不进出图：
  - 接触点：手碰到物体的哪里；
  - 握法：这个物体上说得通的拿法（握法只凭眼睛判断，不要求把包装转向、放大或让印的字读得清）；
  - 移动方向：手往哪个方向动；
  - 物体的反应：动作带来的变化，例如落下的东西、变化的位置或表面； 真实状态来源（issue 109）：商品的状态长什么样只照点名的真实图，见 [photo-scene-product-states.md](references/photo-scene-product-states.md)。
  - 手的大小比例：手和物体放在一起的大小要对得上；
  - 进画面的方向：手或手臂从哪个方向、从身体的哪一侧进入画面，要说得通；没有主人的手，计划里一律拒绝。
- 手按这张卡自己的动作来写，不照抄参考图里的手（见“出图”）。没有手的卡不受这一节影响。
- 特写：每张特写卡在计划里写明它证明什么（例如这个特写要让人看清的那个细节）。没有写明用途的裁切，计划里一律拒绝。
- 同一个地方：整套只在一个地方，就是上面“场景和道具”里计划写的那个地方（一个健身房、一个家、一处工作或通勤、一趟旅行），计划先写明是哪个地方、用到哪几个角落。每张卡换角落、台面、机位和主体，不换地方，最后几张不跳到新的世界。上面“每张换一个新主体”照旧有效：换的是角落和主体，不是地方。

**人物的摄影说明（issue 110；负责人，2026-10-28，CLAUDE.md；来源：Lovart 技能包评审（私有文件夹 work/ 里的评审），Lovart 的文件没有拿进来，关于包装印字的那一句也没有拿）**
- 整个人入画的卡（只有手入画的卡仍归上面“手和动作”一节），套系计划逐张写下面五样，都写成看得见的描述，缺一样的卡不进出图：
  - 主光：主光从哪个方向来，软还是硬，哪些影子留着（取自这张卡研究过的图集和同一个地方；资料包标准 `<资料包目录>/standards/ecommerce-natural-v1/STANDARD.md` 第 3 条“主光方向清楚，阴影与高光一致”是底线，不是全部）；
  - 镜头距离：相机离人多远，人有多少在画面里；
  - 视线：人看向哪里、为什么看那里（看商品、看动作、看画外、看镜头）；
  - 动作：一个和这张卡的小事有关的、有目的的姿势，身体在动，不是静站；站、坐、走三选一，不叠在一起（资料包的人像流程复盘 `<资料包目录>/standards/ecommerce-natural-v1/PORTRAIT-WORKFLOW-REVIEW-2026-10-20.md` 第 3 步：“站姿/坐姿/行走互斥”）；
  - 服装：照负责人的原话，不改写：重画模特，换姿势、多动作、换角度；服装配合这篇帖子的场景。
- 只有夸奖词的说明，计划里一律拒绝：“beautiful premium model”“flawless skin”、精致、高级这类话说不出光从哪来、人在看哪里、身体在做什么，不算摄影说明。
- 同一个人：套系计划写明整套唯一的身份来源：品牌自己的模特图（负责人的规则：模特取自品牌自己的模特图），中式还是欧美按这篇帖子哪个合适来选，写明理由。每张有人的卡都用同一个人，不换脸；人物图只约束身份，姿势、角度和服装按这张卡的摄影说明重画（复盘第 2 步：“人物图约束身份”）。
- 喝东西的卡：喝的动作走上面“手和动作”一节已有的六样（接触点放在杯子和嘴唇上，写清液体的反应），再加这一节的动作和视线，让这一口看起来是真的一刻。
- 资料包里团队的人像提示词技能 `<资料包目录>/prompt-skill/my-precise-image-generation-prompt/SKILL.md`（它自己写明“仅在用户明确要求使用时调用”）里的默认值是一个项目的默认值，不是这套场景里模特的默认值，这里不采用；它在资料包里原样不动。

**打字字体的整套（issue 81；负责人，2026-10-28，对一个客户的十一月第 2 篇：）**
- 适用：套系计划的字体体系一行写明这套的字是打字字体（一种真实的字体：衬线、圆体、无衬线）时。手绘的整套照旧：手绘的字、涂鸦（例如标题旁的小装饰）、笔刷底和其他承托仍然问 Codex；负责人 2026-10-27 的手写字规则（issue 76）不变，手写字仍归 Codex。
- 样式只存一次：打字字体的整套，选定的样式整套只存一次，写进帖子产物目录里的 `typed-styling.json`，字段是 `font_file`（字体文件）、`fill`（填充色）、`outline_width`（描边宽度）、`outline_color`（描边色）、`shadow`（阴影，没选就是 null）、`sizes`（每个标题层级一个字号，例如 main title 和 subtitle），可选 `body`（正文：`font_file`、`fill`、各正文层级字号，没有描边阴影；正文块不用标题的描边和阴影，issue 126）。位置不在样式里：每张卡的字放在哪里，由这张卡的版面计划定。
- 字体：只用免费字体。已装的是起点，现在三种，字形各不相同（A/B/C 字体选项先从这三种里挑）：Noto Serif CJK SC（衬线）和 Noto Sans CJK SC（无衬线），在这台 WSL 的 `/usr/share/fonts/opentype/noto/` 下；LXGW WenKai（霞鹜文楷，楷体，笔画像毛笔字，SIL OFL 1.1 免费商用，issue 116 装上的），文件 `LXGWWenKai-Medium.ttf`，在 `/usr/local/share/fonts/lxgw-wenkai/` 下；`font_file` 可以写文件名（例如 `NotoSerifCJK-Bold.ttc` 或 `LXGWWenKai-Medium.ttf`），设字脚本到这几处和按需装字体的目录里去找。A/B/C 字体选项要一个这三种都没有的字形时（issue 119），用 `python3 skills/builtin/xhs-reference-visual/scripts/install_font.py` 按需装一个免费字体到 `/usr/local/share/fonts/on-demand/`：一次只装一个，只装 OFL 1.1 或 Apache 2.0 许可的，不用为了装而问负责人；没有许可合格的字体合适才问负责人，也不换成系统默认字体。去哪找、许可证怎么查见 [photo-scene-lettering-picks.md](references/photo-scene-lettering-picks.md)。
- 提示词：不让 Codex 画 Easel 自己的打字字：这张卡版面计划里打字字的区域在提示词里留空（写明那里不要字），其余照常；手绘的部分照上面问 Codex。
- 封面也由代码设字：Codex 画出的打字字没有可以量出来、可以照抄的描边宽度和填充值，所以整套从封面起都用同一份样式设字。A/B/C 字体选项里的打字字体，小样也是已经设好字的，负责人选中的就是每一张拿到的。
- 设字：卡画好后，用 `python3 skills/builtin/xhs-note-creator/scripts/text_on_image.py <画好的图> <成图> --styling typed-styling.json --blocks <这张卡的字块文件> --record <这张卡的记录文件>`。字块文件逐块写字（取自确认过的逐字清单）、标题层级和中心位置（取自这张卡的版面计划，用占图宽高的比例）。不裁、不缩放：图保持画好的尺寸。
- 每张卡一份记录：设字时写出，含 `font_file`、`fill`、`outline_width`、`outline_color`、`shadow` 和 `blocks`（每块字的标题层级和实际字号），交付前的打字字体一致检查要用它。

**颜色和层级的对应表（issue 85；负责人，2026-10-28，CLAUDE.md“Photo-scene post images follow one approval process”第 2 步：）**
- 门与写法：`set-plan.md` 里必须有这张表。没有这张表的套系计划没有写完，不交给用户，也不画任何一张卡。层级是 Easel 自己加到照片上的东西，按读者看的先后和轻重分层，例如页头标题、条目编号、对勾、重点划线、标签和备注、箭头、涂鸦；场景自己的颜色和真实包装自己的颜色不是层级，不进表；表不读、不列、不核对包装上印的字（见上面负责人的规则）。每个层级一行，写层级名、一个颜色（颜色名加十六进制值，例如“暖橙 #F28C28”）、这一层覆盖的元素。一层一色：不同的层级不得用同一个颜色，同一个颜色不出现在两行，一个元素只归一行。和字体体系一样，表取自这篇帖子自己的主题研究存下的图集和团队设计记忆（`<资料包目录>/file/DESIGN-MEMORY.md`），计划写明这张表取自哪几套（文件名）。
- 字：打字字体的整套，`typed-styling.json` 里的 `fill`（填充色）和 `outline_color`（描边色）就是“字”这一行的颜色；共用这一份样式的标题层级只有字号不同，是同一行，不是几行；这一行的颜色不得是别的行的颜色；样式文件的字段不变，表去对它，不去改它。封面上给负责人挑的 A/B/C 三种字体样式，用的颜色也不得是别的行的颜色，负责人选中的样式的颜色成为“字”这一行的颜色（表比样式先通过，所以每个选项都要避开别的行）。
- 这是在细化团队标准 `<资料包目录>/standards/ecommerce-natural-v1/STANDARD.md` 里“主色与辅助色……文字层级”那一条，和 `<资料包目录>/playbook/PLAYBOOK.md` 里的“主辅色”：资料包里的这两句原样不动。表在计划页上和套系计划一起交给用户批准；每一行都有十六进制值，计划页（issue 87）靠它画色块。

**图标清单（issue 86；负责人，2026-10-28，CLAUDE.md“Photo-scene post images follow one approval process”第 2 步：）**：`set-plan.md` 里必须有整套唯一一张图标清单，或明写“这套不用图标”；没有清单也没有这句话的套系计划没有写完，不交给用户，也不画任何一张卡。一个图标一个意思，一个意思一个图标。每行写法、什么算图标、和颜色表的关系，全文见 [photo-scene-icon-list.md](references/photo-scene-icon-list.md)，写计划前读完。（字里带表情的卡：表情由出图模型画成 Apple iOS 样式，列进这张清单，细则见 [photo-scene-emoji.md](references/photo-scene-emoji.md)）

## 在 Easel 里怎么落实

**商品和参考图从哪来**
- 真实商品照：当前品牌画像目录里的 `<画像目录>/assets/products/`。商品、包装、Logo 只用这里的真实素材。
- 参考图：品牌画像 `style.md` 的“照片场景帖参考”一节列出了该品牌自己的参考图和品牌文件，路径从画像目录算。最多一张主参考、一张辅助参考。

**确认文案**
- 上图的每一个字（标题、小标签、英文装饰字、便签）先列成逐字清单，用问题工具发给用户确认。清单只含 Easel 自己加到图上的字；真实包装上印的字不进清单、不问用户，包装按真实照片原样放进图。没确认的字不上图。
- 参考图里的功效、测评、前后对比等说法，不照搬，只借视觉结构。不把风格归纳写成全局偏好。

**先画三个封面 A/B/C（issue 88）**

**出图（只走 Codex 订阅，不用 API key）**

- 商品图在前、参考图在后，一条命令传入：

- 每张图的角色由脚本补进提示词：第 1 张是商品，必须原样保留；参考图只借光线、构图和字体风格。场景取自这套的地方和这张卡在套系计划里的小事和道具清单（见上面“场景和道具”，细则见 [photo-scene-setting.md](references/photo-scene-setting.md)）：每张有人的卡，提示词写明这套的地方和它的普通东西，写成看得见的描述；一句把地方剥光的话，例如 “No skincare bottles, no mug, no plants, no books, no laptop, no phone, no decor objects.”，不写，除非这篇帖子研究的图集显示的地方就是光的；提示词写明这张卡的道具，不加其他道具（道具只指小动作里的东西）；不照抄参考图里的人物、婴儿、手和道具（只替换产品的卡除外）。 包装的面（issue 107）：点名的那张照片作为这张卡的商品图，也就是第一个 `--image`。 真实状态来源（issue 109）：显示状态的卡，把点名的来源用 `--state-image` 跟在商品图后面传（商品图在前，只借状态，不借它的场景、道具、人物、手、字），见 [photo-scene-product-states.md](references/photo-scene-product-states.md)。 手绘字的参考图（issue 113）占两个风格参考位中的一个，图片脚本不改。
- 品牌自己的模特是上一条的例外（issue 92；负责人的规则，CLAUDE.md，2026-10-28）：帖子需要人时，模特取自品牌自己的模特图，作为身份参考用单独的 `--identity-image <模特图>` 传入，不算 `--image`，每次至多一张，排在商品图和风格参考之后：`python skills/shared/scripts/ai_image.py img2img --prompt "…" --image <商品图> --image <参考图> --identity-image <模特图> --size 3:4 --output …`。脚本会在提示词里写明这一张是要保持的那个人（脸和身份不变），姿势、角度和服装按这张卡的提示词重画。它是真模特，不是“AI 人物”；负责人的话：重画模特，换姿势、多动作、换角度；服装配合这篇帖子的场景。风格参考仍然不借人物。用哪张图当模特、中式还是欧美，按这篇帖子哪个合适来定，写在套系计划里；品牌没有的人脸不用。身份图只定这个人是谁（脸型、五官、发型），不定皮肤怎么修、修到什么程度和打什么光（issue 117）：品牌商品图是修过的广告图，它的皮肤质感和打光不照抄，提示词里要写明；品牌有同一个模特的几张图时，用最大的、修得最少的那一张。
- 不带包装的人物卡（issue 114）：这张卡有人、没有包装时，只传 `--identity-image`，不传 `--image`：`python skills/shared/scripts/ai_image.py img2img --prompt "…" --identity-image <模特图> --size 3:4 --output …`。Codex 只收到这一张模特图，当作要保持的那个人，不当商品图；提示词写明不画商品和包装（除非这张卡要画），场景、姿势、角度、服装照这张卡的摄影说明写。有商品图的卡照上一条，两个选项都传。风格参考仍然不借人物。
- 有人的卡（issue 110）：提示词带上这张卡的摄影说明（主光、镜头距离、视线、动作、服装），写成看得见的描述，不只写“漂亮的高级模特”；身份图用 `--identity-image`，整套同一张身份来源图（套系计划里写明的那一张）传入，规则见上一条。每张有人的卡，提示词还要用看得见的描述写进（issue 117）：不摆拍的真实一刻、一个看得出来源的主光、没有修图的真实拍出来的皮肤、有重量并有接触的物体（手托住、压住、握住，东西落在台面上有接触阴影）；不为了显得真实而要求颗粒、噪点、色散、固定镜头或失焦，例如 “a little natural noise in the darker areas” 这类句子不写。细则见 [photo-scene-realism.md](references/photo-scene-realism.md)。
- 被拒的姿势（issue 110）：Codex 没有产出图片时，报错里带着 Codex 的最后一句话（“Codex 没有产出图片。它的最后一句话：…”）。这句话显示是被安全策略拒了（坐姿一类的描述容易触发）时，把这张卡的姿势改写成另一个姿势，保持同样的劲头：同一个小事、同样和商品的互动、同样多的动作，再按下面的干净重出重画。不为了绕过拒绝而去掉人物或互动。被拒的原话和新姿势存进这张卡的提示词文件，交付时写明，因为这张卡的姿势和用户批准的计划不同。
- 有手或手臂入画的卡：提示词写明这张卡计划好的接触点、握法、移动方向、物体的反应、手的大小比例和进画面的方向（取自上面“手和动作”），不只写“一只手在搅拌”和“自然的手指”。
- 打字字体的整套（issue 81）：提示词不让 Codex 画 Easel 自己的打字字，打字字的区域留空，手绘的部分照常问；手绘的整套，标题字体体系只写进标题块，另有正文段落写正文样式，参考卡不当图片传；画好后字由代码按 `typed-styling.json` 设上（见上面“打字字体的整套”）。作字体和风格参考传入的封面，用设字之前的封面（Codex 画好的底图），不用已经设过字的成图，Codex 就不会照抄打字字。每张卡的提示词还要求主体、手绘的字、涂鸦和打字字的区域都留在 5% 安全边距里面（issue 104，见 [photo-scene-safe-margin.md](references/photo-scene-safe-margin.md)）。
- 颜色（issue 85）：每张卡的提示词写明这张卡上出现的每个层级的颜色（颜色名加十六进制值，取自对应表，见上面“颜色和层级的对应表”），只管 Codex 画的元素；打字字由代码设，不进提示词，它的颜色就是对应表里“字”这一行。提示词里不用表里没有的颜色，也不让一个颜色同时用在两个层级的元素上。
- 图标（issue 86）：每张卡的提示词逐个写出这张卡上清单里的图标：描述、意思，位置取自这张卡的版面计划，是颜色表里某一层的图标穿那一层的颜色；并写明不画清单以外的任何符号。 字里带表情的卡（easel-setup-gaps issue 100）：提示词对每个表情写明是哪个、在版面计划的哪里、由出图模型画成 Apple iOS 样式，打字的整套设字时不设表情，见 [photo-scene-emoji.md](references/photo-scene-emoji.md)。打字字体的整套也一样，设字只设字，图标仍由 Codex 画。 深色包装（issue 106）：有深色包装的卡，提示词写明至少一个光的办法和一个边的办法（后面更浅的面、暖色主光、边缘光、边缘高光一类），不改包装本身的颜色，不在包装外画描边或光圈，不缩小、裁掉、转向或藏起包装，缺这两样不去画，见 [photo-scene-dark-pack.md](references/photo-scene-dark-pack.md)。 真实包装图层（issue 108）：Codex 把包装改了，先重出；失败的重出到 2 次后，这张卡改用真实包装图层，Codex 只画不带包装的场景（用 `--style-image`，商品照不以商品图的角色传入），真实商品照由 `image_ops.py place` 放进去，见 [photo-scene-real-pack-layer.md](references/photo-scene-real-pack-layer.md)。

**干净重出（issue 78；只对负责人没有批准的卡，已批准的卡见下面“已批准卡的修改”；负责人，2026-10-27；来源：Lovart 技能包评审（私有文件夹 work/ 里的评审））**
- 没有批准的卡，每一次重出，不论原因（AI 感不合格、字画错、版面、道具、套系重复），都从原始商品照（`profiles/<品牌>/assets/products/`）和这张卡选定的参考图重新画，配一条改正过的提示词。命令还是上面那条两张图的命令。
- 没有批准的卡：不得把这张卡已经画出的任何一版当作输入图再传回去，包括“保留这张图，只改某处”“只做这一处改动”这类编辑。在上一版上接着改会越改越脏。
- 套系已通过的封面，画别的卡时仍可以作为字体和风格参考传入：那是另一张卡的第一次画，不是重出。禁止的只是这张卡自己的任何旧版本。A/B/C 对比页或任何拼在一起的图，从不传给 Codex；借选定的封面时传它自己的文件（打字字体的整套传设字之前的底图）。
- 每一版保存的提示词文件写明传入了哪几张图，下次检查才看得出这一版是从哪些图画出来的。两部分（用户的原话、Easel 追加的）也照发出去的样子存进去（issue 112，见 [photo-scene-card-brief.md](references/photo-scene-card-brief.md)）。
- 重出没有次数上限；每一次都照这一节来。重出时先修最高那一级不合格的问题（issue 100，见 [photo-scene-check-order.md](references/photo-scene-check-order.md)）。；只有包装一项例外：真实包装图层（issue 108）， 其他原因的重出仍没有次数上限，见 [photo-scene-real-pack-layer.md](references/photo-scene-real-pack-layer.md)
- 打字字体的整套重出，只重画底图，字再按样式设一遍。

**已批准卡的修改（issue 91；负责人，2026-10-28，CLAUDE.md“Photo-scene post images follow one approval process”第 5 步：）**
- 什么算已批准：只有负责人明确批准过的卡：他选中的封面、他通过的小样，或他并排看过整套后批准的那一套。Easel 自己判断合格的卡不算已批准；拿不准是不是负责人批准的，就按没有批准办（上面的干净重出）。已批准以批准记录 `approvals.json` 为准：有一条有效的才算，没有或已失效就不算（issue 111，见 [photo-scene-approvals.md](references/photo-scene-approvals.md)）。
- 负责人要改一张已批准的卡时，从这张已批准的卡本身改起，不干净重出。 只改负责人点名的地方，其余照已批准的卡原样不动：手、背景、道具、构图、色调。Easel 自己查出这张卡不合格时，也先修最高那一级（issue 100）。
- 已批准的卡用单独的 `--base-image` 传入（issue 115），不再当第 2 张 `--image`：先传真实商品照（真实包装还是要原样，所以商品照照传），再传这张已批准的卡。命令：`python skills/shared/scripts/ai_image.py img2img --prompt "…" --image <真实商品照> --base-image <已批准的卡> --size 3:4 --output …`。已批准的卡不是风格参考，也不算 `--image`，不看图的顺序，由 `--base-image` 明确指定；文件顺序还是商品照在前、已批准的卡紧跟在后。脚本会在提示词里写明第 2 张是要保留的底图：它的画面（手、背景、道具、构图、色调）原样保留，只改提示词点名的地方，这一句不带风格参考的说法，所以提示词不用再去改写脚本的角色说明。提示词里只写负责人点名的那一处（负责人的话照抄）。风格参考和身份参考照旧可以一起传，它们的编号按实际顺序排在底图之后；每次至多 1 张底图，付费 API 路线收到 `--base-image` 会直接报错。传入之前先跑 `approvals.py check`（issue 111），这张卡的条目有效才传。
- 打字字体的整套（issue 81）：传入的是已批准的卡设字之前的底图（Codex 画好的那一张），不是已经设过字的成图；画面改好之后，字再按 `typed-styling.json` 设一遍。负责人要改的本身就是打字字体的字（改字、改位置、改字号）时，不重画：只把字重新设一遍。
- 并排检查：改好的卡交付之前，和已批准的那一版并排看，图对图，不只对提示词。负责人没点名的任何一处变了，这张卡不合格，例如手、背景、产品大小或色偏。不合格的卡仍然从已批准的卡改起重画，或如实报告给用户，不能当合格交付。下面“交付前检查实际图片”里已有的各项检查（AI 感检查、手和动作检查、真实包装的眼睛检查、字的检查）照样都做，也都不读包装上印的字。
- 每一版保存的提示词文件，除了写明传入了哪几张图，还写明它是从哪一个已批准的版本改出来的，并逐字写下负责人要改的那一句话。 失败的重出次数也写在这里（issue 108，已批准卡的修改也算同一个次数，到 2 后按真实包装图层办，见 [photo-scene-real-pack-layer.md](references/photo-scene-real-pack-layer.md)）。用户的原话两部分也存进去（issue 112，见 [photo-scene-card-brief.md](references/photo-scene-card-brief.md)）。

**交付前检查实际图片**
